# reports/ — 制作レポート置き場

新しく作ったものをポートフォリオに載せたいときは、**このフォルダにレポートを置くだけ**です。
毎日の定期実行(Claude のスケジュールタスク)がここを確認し、新しいレポートがあれば
ポートフォリオ用の形式に変換して作品ページに追加し、公開まで行います。

## 置き方

### パターン1: md ファイル1つだけ

```
reports/
└── 2026-07-27-myapp.md
```

### パターン2: 画像や配布ファイルも一緒に(フォルダ)

```
reports/
└── myapp/
    ├── report.md        ← レポート本体(ファイル名は自由)
    ├── screenshot.png   ← スクリーンショット(自動で作品画像になる)
    └── MyApp.zip        ← 配布したいファイル(ダウンロード作品のみ)
```

## レポートの書き方

[_TEMPLATE.md](_TEMPLATE.md) をコピーして書くのが確実です。
最低限 `name:` があれば動きます。書き方が多少崩れていても、定期実行の Claude が
内容を読んで適切な形に整えてくれます。

## 処理の流れ

1. 毎日の定期実行が `npm run ingest` を実行(手動で実行してもOK)
2. レポートが `src/content/works/`(または `downloads/`)の md に変換される
3. 画像は `public/images/projects/` へ、配布ファイルは `public/downloads/` へコピー
4. 処理済みレポートは `reports/archive/` へ移動(このフォルダは git 管理外)
5. ビルド確認 → コミット → push → Vercel / GitHub Pages に自動デプロイ

## 注意

- このフォルダの中身(README と _TEMPLATE 以外)は **git にコミットされません**。
  ラフなメモを置いても公開リポジトリには出ないので安心してください。
- 変換だけ試したいときは `npm run ingest -- --dry-run`
