# reports/ — 制作レポート置き場

新しく作ったものをポートフォリオに載せたいときは、**このフォルダにレポートを置くだけ**です。
毎日の定期実行がここを確認し、新しいレポートがあればポートフォリオの形式に変換して、公開まで行います。

## 置き方

### md ファイル1つだけ

```
reports/
└── 2026-10-20-myapp.md
```

### 画像や配布ファイルも一緒に（フォルダ）

```
reports/
└── myapp/
    ├── report.md        ← レポート本体（ファイル名は自由）
    ├── screenshot.png   ← スクリーンショット（自動で作品の画像になる）
    └── MyApp.zip        ← 配布したいファイル（ダウンロードに載せる場合のみ）
```

## 書き方

[_TEMPLATE.md](_TEMPLATE.md) をコピーして書くのが確実です。最低限 `name:` があれば動きます。
多少崩れていても、定期実行が下の表記ルールに合わせて整えます。

### 作品ページの見出し（全作品で共通）

1. 概要 — 何を作ったか
2. 特徴 — 主な機能やポイント（箇条書き）
3. 対象 — 誰のためのものか
4. 作った理由 — きっかけや目的
5. 成果と学び — できるようになったこと、今後

古い見出し（主な機能・目的・成果 など）で書いても、取り込み時に自動でこの名前にそろえます。

### 表記ルール

- 文体は「です・ます」。見出しだけ体言止め
- 約物は全角（、。！？「」（））、英数字は半角。和文と英数字の間にスペースは入れない
- 技術名は公式の表記（JavaScript、Three.js、Firebase、GarageBand など）
- 「作る」は漢字、「もの」はひらがな
- `summary`（一覧カードの紹介文）は「〜です。」で終わる1文
- `date` は `YYYY-MM`
- 書かれていないことは足さない（定期実行も事実の追加はしません）

## 処理の流れ

1. 定期実行が `npm run ingest` を実行（手動でも可）
2. レポートが `src/content/works/`（または `downloads/`）の md に変換される
3. 画像は `public/images/projects/` へ、配布ファイルは `public/downloads/` へコピー
4. 処理済みのレポートは `reports/archive/` へ移動（git 管理外）
5. 表記をそろえ、ビルドを確認して、コミット → push → Vercel が自動で公開

## 配布ファイルの安全チェック

配布ファイルと画像は誰でもダウンロードできるため、`npm run build` の前に自動で中身を検査します（`npm run check:files` で単体実行も可）。zip・jar・apk は展開して1ファイルずつ調べます。次のものが見つかるとビルドが止まり、公開されません。

- `.env`、秘密鍵（`.pem` `.key` `.p12`、SSH の鍵）、署名用キーストア（`.jks` `.keystore`、`key.properties`）
- クラウドの認証情報（`google-services.json`、`GoogleService-Info.plist`、サービスアカウントの JSON など）
- API キー・トークン（AWS、Google / Firebase、GitHub、Stripe、Resend、Slack、AI サービスなど）
- このPCのフォルダのパス（`/Users/ユーザー名/...`）、`.git` フォルダ、データベース（`.db` `.sqlite`）
- `.DS_Store`、`__MACOSX`（macOS の「圧縮」で入るもの）、写真の位置情報（GPS）
- 中身を確認できない形式（`.dmg` `.7z` `.rar` など）とパスワード付きの zip

止まったときは、該当ファイルを取り除いてから zip を作り直してください。アプリは実行に必要なもの（`.app` や `.jar` 本体と説明書き）だけを入れ、ソースコードやビルド用のフォルダは入れないのが基本です。macOS では Finder の「圧縮」ではなく、ターミナルで `zip -qryX <名前>.zip <フォルダ> -x '*.DS_Store'` を使うと、`.DS_Store` と `__MACOSX` が入りません（`-y` で `.app` の中のリンクもそのまま保てます）。

## 注意

- このフォルダの中身（README と _TEMPLATE 以外）は **git にコミットされません**
- 変換だけ試したいときは `npm run ingest -- --dry-run`
