# 編集モード 設計書

- 日付: 2026-11-09
- 状態: 合意済み(本人と対話で決定)

## 目的

ポートフォリオの文章と画像を、本人が手元のMacのブラウザ上で直接書き換えられるようにする。書き換えた内容は下書きとして保存され、本人が Claude に「公開して」と伝えると、Claude が下書きを読み、表記とレイアウトを整えて公開する。

外部サービスや既製の CMS は使わない。依存パッケージも増やさない(このサイトは自前の軽量パーサーで運用している方針を守る)。

## 範囲

### 対象

- **サイトに表示される文章すべて**
  - 作品・ダウンロード: 画面に出る frontmatter の項目と本文(リード文、各セクションの見出しと本文)
  - プロフィール系のデータ: 名前、所属、キャッチコピー、MVV、興味、スキル名、歩み、いま取り組んでいること、ナビの表示名
  - ページや部品に直書きされている文言: 見出し、ボタン、導入文、問い合わせフォームの項目名・入力例・送信結果メッセージ、フッターなど
- **画像**: 作品・ダウンロードの画像(`image`)の差し替えと、その説明文(`imageAlt`)、注記(`imageCaption`)、表示方法(`imageFit`)
- **画面に出ない項目**: 作品・ダウンロードの日付、タグ、公開URL、GitHub URL

### 対象外

- 作品・ダウンロードの追加・削除・並べ替え(追加は今まで通り `reports/` へ)
- 歩み・MVV などの項目そのものを増やす・減らす
- トップの3Dの代わりに出す画像(`mouse-model.png`)、OG 画像、`index.html` の検索・SNS 向け説明文
- 公開サイト上での編集(編集は手元の Mac だけで行う)

## 使い方(本人)

1. `npm run edit` を実行するか、リポジトリ直下の `編集する.command` をダブルクリックする。編集モードのサイトがブラウザで開く。
2. 文章をクリックして書き換える。画像は「画像を差し替え」から選ぶ。変更は確定するたびに下書きへ自動保存される。
3. 伝えたいことがあれば編集バーの「Claudeへのメモ」に書く。
4. Claude に「保存したよ」「公開して」と伝える。

## 全体構成

```
src/content/
├── works/*.md, downloads/*.md   作品・ダウンロード(形式は変更しない)
├── copy.json      【新規】ページと部品に直書きされていた文言
├── copy.js        【新規】copy.json を読む t() 関数
├── site.json      【新規】site.js にあったプロフィール系データ
└── site.js        site.json を読み込み、今と同じ名前で書き出すだけにする(表記ルールのコメントは残す)

src/lib/
├── markdown-parse.js   【新規】既存パーサーのうち React に依存しない部分(frontmatter・セクション・リード)
└── markdown.jsx        markdown-parse.js を再公開し、表示用の RichText / BlockList だけを持つ

src/editor/
├── index.jsx      本番用。Editable などは中身をそのまま表示するだけ、EditorRoot は何も描かない
├── live/          編集モード用の実装(編集バー、文章・画像の編集、設定パネル)
└── patch.js       md / json の指定箇所だけを書き換える純粋関数(サーバーとテストで共用)

scripts/
├── editor/vite-plugin.mjs   編集モードの dev サーバー拡張(下書きの読み込み・保存窓口)
├── editor-apply.mjs         下書きを本物へ反映する(Claude 用)
├── text-snapshot.mjs        全ページの表示テキストを書き出す(前後比較用)
└── check-no-editor.mjs      本番ビルドに編集機能が混ざっていないか検査(postbuild)

tests/                       node --test で動く単体テスト(依存追加なし)
docs/editor.md               使い方と、Claude の公開手順
CLAUDE.md                    「公開して」と言われたら docs/editor.md の手順に従う旨
編集する.command              ダブルクリック用の起動ファイル
```

### 下準備: 文言の集約

- ページと部品に直書きされている文言をすべて `copy.json` に移す。キーは `ページ.場所.項目` のドット区切り(例: `home.cta.title`)、値は文字列の平らなオブジェクトにする。共通部品は `common.*`、ナビとフッターは `layout.*`。
- 文言の中にデータを差し込む箇所は `{name}` の形で書き、`t('home.lead', { affiliation, nameJa })` のように渡す。
- `site.js` のデータは `site.json` へ移す。`site.js` はそれを読み込んで `PROFILE`、`MVV` など今と同じ名前で書き出すので、各ページの読み込み方は変わらない。
- **移し替えの前後で、全ページの表示テキストと属性(alt、placeholder、aria-label、title)を `text-snapshot.mjs` で書き出し、1文字も変わっていないことを確認してから次に進む。**

### 本番との切り離し

- 各ページは `src/editor/index.jsx` から `Editable`、`EditableImage`、`EditorRoot` を読み込む。本番用の実装は素通しで、編集の仕組みは一切持たない。
- `vite --mode edit` のときだけ、`vite.config.js` の alias で `src/editor/index.jsx` を `src/editor/live/index.jsx` に差し替え、編集用プラグインを有効にする。
- `npm run build` の後に `check-no-editor.mjs` を実行し、ビルド結果に編集モード専用の目印文字列が含まれていたら失敗させる。Vercel のビルドでも同じ検査が走る。

## 下書き

```
.editor/                         Git 管理外(.gitignore に追加)
├── drafts/                      本物と同じ並びの下書き
│   ├── src/content/works/gamebar-toki.md
│   ├── src/content/copy.json
│   └── public/images/projects/gamebar-toki-20261109.jpg
├── manifest.json                下書きごとに、作り始めた時点の本物のハッシュを記録(衝突検出用)
├── notes.md                     Claude へのメモ
└── history/<日時>/              公開済みの下書きの控え
```

- 編集モードの dev サーバーは、`src/content/` のファイルを読み込むとき、下書きがあれば下書きを返す(プラグインの `load`)。`/images/projects/` へのリクエストも下書きを優先して返す。
- 下書きが書き換わると、該当モジュールを再読み込みしてページを即座に更新する。編集バーの状態は保たれる。
- 下書きは `src/content/` の外かつ Git 管理外なので、毎日の定期実行(`portfolio-report-ingest`)が書きかけを公開することはない。定期実行の設定は変更しない。

## 保存窓口

編集モードの dev サーバーに `/__editor/` 以下の窓口を追加する。

| 窓口 | 役割 |
|------|------|
| `GET /__editor/state` | 下書きの一覧(ファイル、衝突の有無)とメモを返す |
| `POST /__editor/patch` | 指定箇所を書き換えて下書きに保存する |
| `POST /__editor/image` | 画像を下書きに保存し、対象の `image` を新しいパスにする |
| `POST /__editor/discard` | 指定した下書き(または全部)を取り消す |
| `PUT /__editor/notes` | メモを保存する |

### 安全策

- dev サーバーは `127.0.0.1` にだけ接続を許す(同じネットワークの他の機器からはつながらない)。
- 窓口は `X-Editor: 1` ヘッダーがあり、Origin と Host が自分自身のときだけ受け付ける。開いている他のサイトから書き込まれることを防ぐ。
- 書き換えられるのは許可したファイルだけ: `src/content/works/<id>.md` と `src/content/downloads/<id>.md`(既にあるもの)、`src/content/copy.json`、`src/content/site.json`。書き込み先は正規化したうえで `.editor/drafts/` の中であることを確かめる。
- 画像は PNG と JPEG だけを受け付け、拡張子ではなくファイル先頭のバイトで形式を確かめる。上限は 10MB。

## 書き換え(patch.js)

書き換える場所は次の形で指定する。

| 対象 | 指定 |
|------|------|
| copy.json | `{ file: 'src/content/copy.json', key }` |
| site.json | `{ file: 'src/content/site.json', path: ['MVV', 0, 'text'] }` |
| frontmatter の1項目 | `{ file, field }` |
| リード文 | `{ file, part: 'lead' }` |
| セクション | `{ file, section: <番号>, part: 'title' \| 'body' }` |

- 指定した場所以外は1文字も変えない(ほかの行、コメント、項目の順番を保つ)。
- frontmatter の値は1行。タグはカンマ区切りで受け取り `[a, b]` の形で書く。値に「 #」、前後の空白、`[` や引用符で始まる文字列、`true`/`false` が含まれる場合は引用符で囲み、既存のパーサーで同じ値として読めるようにする。
- 本文は「空行で段落を分け、`- ` で始まる行は箇条書き」の形のまま書く。
- JSON は2スペースのインデントで、キーの順番を保って書き出す。
- 書き換えた後に既存のパーサーで読み直し、狙った値になっていることをテストで保証する。

## 編集画面

### 編集バー(画面下に固定)

- **編集 / 閲覧** の切り替え。編集中は文章や画像をクリックすると編集になり、リンクやボタンは動かない。閲覧に切り替えると普通にページを移動できる。どちらも下書きを反映した見た目になる。
- **変更 N件**(ファイル単位)。押すと一覧が出て、1件ずつ取り消せる。作り始めた後に本物が更新されていれば「元のファイルが更新されています」と表示する。
- **このページの設定**(後述)
- **Claudeへのメモ**
- **すべて取り消す**(確認つき)

見た目はサイトのデザイントークン(`tokens.css`)に合わせる。

### 文章

- 編集できる文章にマウスを乗せると点線の枠が出る。
- **短い文**(作品名、見出し、ボタン、ナビ名、紹介文、担当など): その場で書き換える。Enter で確定、Esc で取り消し、外をクリックしても確定。**日本語入力の変換中の Enter では確定しない。** 改行は入らない。
- **本文**(段落や箇条書きのあるもの): クリックすると、ページと同じ文字の見た目の入力欄に切り替わる。空行で段落、`- ` で箇条書き。段落や項目の追加・削除も自由。外をクリックするか Cmd+Enter で確定、Esc で取り消し。
- 貼り付けは文字だけにする(他所の装飾を持ち込まない)。
- `{…}` の差し込みを含む文言は、編集中に `{…}` をそのまま表示し、「自動で入る部分です」と添える。差し込みを消したり名前を変えたりした場合は、確定の前に警告する。

### 画像

- 差し替えられる画像にマウスを乗せると「画像を差し替え」が出る。クリックしてファイルを選ぶか、画像の上にドラッグ&ドロップする。
- **ブラウザの中で描き直してから保存する。** 位置情報などの埋め込み情報はこのとき消え、長辺が 2400px を超える場合は縮小する。元が PNG なら PNG、それ以外は JPEG(品質 0.88)にする。
- 読み込めない形式(HEIC など)は「JPEG か PNG で書き出してから選んでください」と表示する。
- ファイル名は `<作品・ダウンロードのid>-<YYYYMMDD>.<拡張子>` にする(同じ名前で上書きするとブラウザのキャッシュで古い画像が出ることがあるため)。
- 差し替えた後、その画像の説明文(`imageAlt`)の入力欄を開いて確認を促す。

### このページの設定(パネル)

- 作品・ダウンロードのページ: 日付、タグ、公開URL、GitHub URL、画像の説明文・注記・表示方法(枠いっぱい / 全体を表示)。
- すべてのページ: そのページの文言のうち、クリックでは直せないもの(入力欄の入力例、読み上げ用のラベル、送信結果のメッセージ、ブラウザのタブに出るタイトルなど)を一覧で書き換えられる。copy.json のキーの接頭辞(`contact.*` など)と `common.*`、`layout.*` から集める。

## 公開の流れ(Claude)

本人に「保存したよ」「公開して」と言われたら、`docs/editor.md` の手順で次を行う。リポジトリ直下の `CLAUDE.md` からこの手順を参照させ、どのセッションでも同じ手順で動くようにする。

1. main で `git pull` し、作業ツリーがきれいなことを確かめる。
2. `npm run editor:apply -- --dry-run` で、下書きと本物の差分と衝突の有無を見る。`.editor/notes.md` を読む。
3. `npm run editor:apply` で下書きを本物へ反映する。反映した下書きは `.editor/history/<日時>/` へ移る。
4. 表記ルール(`site.js` の冒頭と `reports/README.md`)に合わせて、誤字・表記・軽い言い回しを整える。意味は変えず、事実は足さない。
5. 変更のあったページを PC 幅(1280px)とスマホ幅(375px)のブラウザで開き、文の長さでレイアウトが崩れていないか確かめる。崩れていれば、文かレイアウトを直す。
6. `npm run build`(配布ファイルの安全チェックと、編集機能の混入チェックを含む)。
7. `text-snapshot.mjs` で公開前後の表示テキストを比べ、下書きで変えたところと 4・5 で直したところ以外が変わっていないことを確かめる。
8. 差し替えで使われなくなった古い画像は、ほかから参照されていなければ削除する(Git の履歴には残る)。
9. コミットして push し、本番に反映されたことを確かめる。
10. 報告する: 本人の変更の要約、Claude が手を入れた箇所の「直す前 → 直した後」すべて、確認した画面。

### 公開の前に止まって本人に聞くとき

- 事実が怪しいとき、または意味が変わる直しが必要になったとき
- 下書きを作り始めた後に、同じファイルが定期実行などで更新されていたとき(`editor:apply` は衝突があると反映しない)
- メモに Claude への質問や判断してほしいことが書かれているとき

公開後に戻したいときは `git revert` で戻せる。

## 道具

- **`scripts/editor-apply.mjs`**: `--dry-run` で差分と衝突を表示する。衝突があれば反映しない。反映後、下書きを `history/` へ移し、使われなくなった画像の候補を表示する(削除はしない)。
- **`scripts/text-snapshot.mjs`**: ビルド済みのサイトを手元で配信し、ヘッドレスの Chrome(`/Applications/Google Chrome.app`。OG 画像の書き出しで既に使っている)で全ページ(全作品・全ダウンロードの詳細を含む)を開き、表示テキストと属性を1つのテキストファイルに書き出す。依存は増やさない。
- **`scripts/check-no-editor.mjs`**: `postbuild` で実行し、`dist/` に編集モード専用の目印が含まれていればビルドを失敗させる。

## テスト

- `npm test`(`node --test tests/`)。依存は増やさない。
- 単体テストの対象:
  - patch.js: 各対象の書き換えが狙いどおりで、ほかの行が変わらないこと。既存パーサーで読み直して値が一致すること。frontmatter の引用符の付け方
  - 保存窓口の検証: 許可リスト外のファイル、`..` を含むパス、Origin や Host の違うリクエストを拒否すること。画像形式の判定
  - editor-apply: 衝突の検出、`--dry-run` で何も変えないこと
  - 文言: コード中の `t('…')` のキーがすべて copy.json にあり、copy.json に使われていないキーがないこと
- 編集画面は、実際のブラウザで編集・確定・取り消し・画像の差し替えまで操作して確かめる。日本語入力の変換中の Enter も確かめる。

## 進め方

- ブランチ `feature/editor`(作業フォルダ `.claude/worktrees/editor`)で作る。main は触らないので、作業中に定期実行とぶつからない。
- 順番: 文言の集約とスナップショットでの不変確認 → patch.js とテスト → 保存窓口と下書きの読み込み → 文章の編集画面 → 画像の差し替え → 設定パネルとメモ → 公開手順と文書 → 通しで確認 → main へ fast-forward で取り込み、push。
