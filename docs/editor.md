# 編集モード

サイトの文章と画像を、このMacのブラウザの上で直接書き換えるための仕組みです。書き換えた内容は**下書き**として保存され、公開サイトにはすぐには出ません。Claude に「公開して」と伝えると、表記とレイアウトを整えてから公開されます。

外部のサービスは使っていません。公開サイトには編集の仕組みは入っていません(ビルドのたびに自動で確かめています)。

## 使い方

### スキルツリーの配置・ノードを編集する

`スキルツリーを編集.command` をダブルクリックするか、`npm run edit:skills` を実行します。通常の編集モードの「スキルツリーを配置」からも開けます。

1. ノードを選び、ドラッグして配置します。背景のドラッグは画面移動です。「画面を動かす」に切り替えるとノード上からも画面を移動できます。
2. 名前・接続先・色・形・大きさ・ロゴは右側で編集して「変更を適用」を押します。形は円・菱形・四角・六角形、大きさは44〜112pxです。自分自身と子孫は接続先に選べません。
3. 「下書きを保存」を押します。公開は別の操作です。本人が「公開して」と伝えたとき、下の公開手順で反映します。

ノード追加・削除と元に戻す・やり直すに対応しています。削除したノードの子は、その元の親へつなぎ直します。JSONを書き出せば別の配置を控えにでき、読み込みで復元できます。未保存の変更がある状態で画面を閉じると確認が出ます。別のタブによる更新や接続の循環は保存時に止めます。

「接続線の形」で直線・折れ線・曲線を選び、「線の曲がり」で経路を調整できます。ノード一覧・ノード選択・接続先・ロゴ候補はA–Z順です（制作元は先頭、日本語名は英字名の後）。座標や形は並び替えで変わりません。以前のJSONバックアップも読み込めますが、廃止した「分野をまたぐ関連先」は読み込み時に取り除きます。

「経験の区分」は制作・授業・間接利用など、「習熟度」はLv.1〜5の自己評価です。未確認のレベルは「自己評価待ち」のままにします。形・大きさや掲載実績数からレベルを自動で付けることはありません。

元データは `src/content/skill-tree.json`、下書きは `.editor/drafts/src/content/skill-tree.json` です。ロゴの候補は `src/content/skill-icons.json` で管理します。スキルの追加・削除は `site.json` ではなく、この専用エディターで行ってください。

### 開く

リポジトリの `編集する.command` をダブルクリックするか、ターミナルで次を実行します。ブラウザで編集モードのサイトが開きます。

```bash
npm run edit
```

閉じるときは、ターミナルで Ctrl+C を押すか、ウィンドウを閉じます。下書きは残ります。

### 文章を直す

- 直せる文章にマウスを乗せると点線の枠が出ます。クリックするとその場で書き換えられます。
- 1行の文章は **Enter で確定、Esc で取り消し**。外をクリックしても確定します。日本語の変換中の Enter では確定しません。
- 作品の本文はクリックすると入力欄になります。**空行で段落を分け、「- 」で始まる行は箇条書き**です。Cmd+Enter か外をクリックで確定します。
- `{nameJa}` のような `{…}` は、名前などが自動で入る部分です。消さないでください(消すと確認が出ます)。
- 編集中はリンクやボタンが動きません。ページを移動するときは、画面下の編集バーで「閲覧」に切り替えます。

### 画像を差し替える

作品やダウンロードの画像にマウスを乗せ、右上の「画像を差し替え」を押すか、画像の上にファイルをドラッグ&ドロップします。

- 保存する前にブラウザの中で描き直すので、写真に埋め込まれた位置情報などは自動で消えます。長辺が 2400px より大きい写真は縮小されます。
- PNG は PNG のまま、それ以外は JPEG で保存されます。iPhone の HEIC は読み込めないので、JPEG か PNG で書き出してから選んでください。
- 差し替えると「このページの設定」が開くので、画像の説明文(読み上げ用)も確かめてください。

### 画面に出ない項目(このページの設定)

編集バーの「このページの設定」から直せます。

- 作品のページ: 制作時期、使用技術、公開URL、GitHub URL、画像の説明文・注記・表示方法など
- ダウンロードのページ: 公開時期、ファイルサイズ、対応環境など
- すべてのページ: クリックでは直せない文言(送信結果のメッセージ、読み上げ用のラベル、ブラウザのタブのタイトルなど)と、プロフィールの基本情報

### 下書きを確かめる・取り消す

- 「変更 N件」で、下書きのあるファイルが並びます。1件ずつ取り消せます。
- 「すべて取り消す」で下書きを全部消します(元に戻せません)。

### 公開してもらう

伝えたいことがあれば、編集バーの「Claudeへのメモ」に書いておきます。そのうえで Claude に「保存したよ」「公開して」と伝えてください。

Claude は誤字・表記の統一・軽い言い回しの調整をして、レイアウトを確かめてから公開します。意味は変えず、事実も足しません。手を入れた箇所は「直す前 → 直した後」で報告します。

### 編集モードで直せないもの

作品・ダウンロードの追加・削除・並べ替え、歩みや MVV などの項目を増やす・減らすこと、トップの 3D の代わりに出す画像、OG 画像、検索・SNS 向けの説明文。必要なときは Claude に頼んでください(作品の追加は今までどおり `reports/` へ)。スキルのノードは上記の専用エディターから追加・削除できます。

## しくみ

| 場所 | 役割 |
|------|------|
| `src/content/copy.json` | ページや部品の文言 |
| `src/content/site.json` | プロフィール・歩み・MVV など |
| `src/content/works/` `downloads/` | 作品・ダウンロード(今までどおり) |
| `src/editor/index.jsx` | 文章や画像を表示する部品(本番用。値をそのまま出すだけ) |
| `src/editor/live/` | 編集モード用の部品・編集バー・パネル |
| `src/editor/patch.js` | 指定した場所だけを書き換える関数 |
| `scripts/editor/` | 編集モードの Vite プラグイン(下書きの読み込み・保存窓口) |
| `scripts/editor-apply.mjs` | 下書きを本物へ反映する |
| `scripts/text-snapshot.mjs` | 全ページの表示テキストを書き出す(公開前後の比較用) |
| `scripts/check-no-editor.mjs` | 本番ビルドに編集の仕組みが混ざっていないか確かめる |

下書きは `.editor/`(Git 管理外)に、本物と同じ並びで置かれます。`src/content/` 自体は書き換えないので、毎日の定期実行が書きかけを公開することはありません。

```
.editor/
├── drafts/        下書き(本物と同じ並び。画像は drafts/public/images/projects/)
├── manifest.json  下書きを作り始めたときの本物のハッシュ(衝突の検出用)
├── notes.md       Claude へのメモ
└── history/       公開した下書きの控え(日時ごと)
```

保存窓口(`/__editor/*`)はこのMacからしかつながらず、`X-Editor` ヘッダーの付いたリクエストだけを受け付けます。書き換えられるのは上の表の content のファイルだけです。

## 公開の手順(Claude 向け)

本人に「保存したよ」「公開して」と言われたら、次の順に進める。表記ルールは `src/content/site.js` の冒頭と `reports/README.md`。

1. **準備**: `/Users/toki/Developer/Web/Portfolio` で main にいること、`git status --short` が空であることを確かめ、`git pull --ff-only` する。
2. **確認**: `npm run editor:apply -- --dry-run` で差分・衝突・メモを読む。
   - 衝突がある(終了コード 2)、メモに質問や判断してほしいことがある、事実が怪しい・意味が変わる直しが要る、のどれかなら、**ここで止めて本人に聞く**。
3. **基準を取る**: `npm run build && npm run snapshot -- output/snapshots/before-publish.txt`
4. **反映**: `npm run editor:apply`。使われなくなった画像の候補が出たら控えておく。
5. **整える**: 反映された差分(`git diff`)を読み、誤字・表記ルール・軽い言い回しを直す。意味は変えず、事実は足さない。直した箇所はすべて「直す前 → 直した後」を記録する。
6. **レイアウト確認**: `npm run dev` で、変更のあったページを PC 幅(1280px)とスマホ幅(375px)で開き、文の長さで崩れていないか確かめる。崩れていれば文かレイアウトを直す。
7. **ビルドと比較**: `npm run build`(安全チェックと編集機能の混入チェックを含む)→ `npm run snapshot -- output/snapshots/after-publish.txt` → `diff output/snapshots/before-publish.txt output/snapshots/after-publish.txt`。下書きと手順5・6で直したところ以外が変わっていないことを確かめる。
8. **画像の片付け**: 4で出た候補が、ほかから参照されていないことを `grep -rn <ファイル名> src` で確かめてから `git rm` する。
9. **公開**: `src/content/` `public/images/projects/`(と手順6でレイアウトを直したファイル)だけをコミットし、`export GH_TOKEN="$(gh auth token --user toki-0508)"` のあと `git push`。Vercel の本番(https://tomoki-arai.vercel.app/)に反映されたことを確かめる。
10. **報告**: 本人の変更の要約、Claude が手を入れた箇所の「直す前 → 直した後」すべて、確かめた画面。公開後に戻したいときは `git revert` で戻せることも添える。

## 困ったとき

- **ポートが使われている**: ほかに `npm run dev` が動いていると、編集モードは別の番号で開きます。ターミナルに出た URL を開いてください。
- **「元のファイルが更新されています」と出た**: 下書きを作り始めた後に、定期実行などで同じファイルが更新されました。そのまま Claude に公開を頼めば、どちらを残すか確認されます。
- **編集バーが出ない**: `npm run dev` ではなく `npm run edit` で開いているか確かめてください。
